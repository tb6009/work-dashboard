# 이미지 제작프로세스최적화

> 동일 장면을 빠르게 만드는 방식과, 투시·카메라·공간 구조를 검증하며 정교하게 만드는 방식을 목적에 따라 선택하고 비용을 줄이는 운영 문서

## 2. 최적화 목표

이미지 제작 최적화는 단순히 호출 횟수를 줄이는 것이 아니다. 다음 네 비용의 총합을 낮추는 것이다.

1. **생성 비용**: 프롬프트 작성과 이미지 생성 호출
2. **검증 비용**: 투시·형태·접지·색·광학 검사
3. **재작업 비용**: 오류가 발견된 단계까지 되돌아가는 비용
4. **변형 비용**: 동일 공간의 다른 카메라·렌즈·조명·색 버전을 만드는 비용

최적화 대상은 다음 식으로 관리한다.

```text
총 제작비용 = 초기 구축비용 + 생성 호출비용 + 검증비용 + 실패 재작업비용 + 파생 버전 비용
```

01 방식은 초기 구축비용이 낮고 재작업·파생 비용이 높다. 02 방식은 초기 구축비용이 높지만 동일 공간의 파생 버전이 늘어날수록 평균 비용이 낮아진다.

## 3. 방식 선택 기준

| 상황 | 권장 방식 | 이유 |
|---|---|---|
| 아이디어 스케치 1–3장 | 01 | 초기 속도가 가장 빠름 |
| 구조 정확도가 낮아도 되는 분위기 이미지 | 01 | 투시 계측 비용이 불필요 |
| 최종 결과 한 장, 납기 매우 짧음 | 01+최소 검증 | 비용 대비 효율적 |
| 건축·가구 직선이 중요한 이미지 | 02 | 카메라 행렬과 강체 구조 필요 |
| 동일 공간의 여러 카메라 앵글 | 02 | 3D 공간을 재사용할 수 있음 |
| 24/35/50mm 렌즈 비교 | 02 | 렌즈값만 변경 가능 |
| Sony/Canon A/B 비교 | 02 | 동일 기하·조명 마스터를 공유 가능 |
| 캠페인용 다수 파생 이미지 | 02 | 초기 비용을 여러 결과에 분산 |

## 4. 토큰과 시간의 상대 모델

정확한 토큰 수와 생성시간은 모델·해상도·서비스 상태에 따라 달라진다. 아래 값은 이번 사례를 바탕으로 한 **상대 계획값**이며 실제 사용량이 아니다.

| 방식 | 텍스트 작업량 | 이미지 호출 | 초기 시간 | 파생 1장 비용 | 검증 가능성 |
|---|---:|---:|---:|---:|---|
| 01 단일 생성 | 1× | 1× | 1× | 1× | 낮음 |
| 01 반복 수정 | 2–4× | 2–5× | 2–5× | 1–3× | 중간 |
| 02 하네스 | 3–6× | 3–6× | 4–8× | 0.4–1× | 높음 |
| 02 3D+합성 | 4–8× | 2–5× | 6–12× | 0.2–0.7× | 가장 높음 |

핵심은 파생 수량이다. 같은 공간에서 앵글·렌즈·조명·카메라 색을 여러 개 만들면 02 방식의 3D 마스터 구축비용이 재사용되므로 장당 평균비용이 감소한다.

## 5. 통합 최적화 파이프라인

```text
목적·파생 수량 결정
  ↓
01 또는 02 방식 선택
  ↓
저해상도 구성 검토
  ↓
기하 필요 시 카메라·공간 잠금
  ↓
인물·오브젝트·조명 제작
  ↓
카메라·렌즈·색 분기
  ↓
자동 검증 → 사람 검토
  ↓
통과본만 고해상도 출력
```

## 6. 비용을 줄이는 핵심 규칙

1. **고해상도 생성은 마지막 한 번만 한다.** 구성·투시는 저해상도 제어도로 검증한다.
2. **한 번에 한 변수만 바꾼다.** 수정 원인을 추적할 수 있어 재시도 프롬프트가 짧아진다.
3. **공통 마스터를 먼저 만든다.** Sony·Canon, 오전·야간, LUT 차이는 마지막에 분기한다.
4. **기하 실패 시 외관 작업을 중단한다.** 잘못된 투시 위에 조명과 색을 쌓지 않는다.
5. **실패본을 삭제하지 않는다.** 실패 원인과 좌표를 남겨 같은 오류 프롬프트를 반복하지 않는다.
6. **카메라값과 미학적 표현을 분리한다.** 35mm 투시는 카메라 행렬로, Sony·Canon 감성은 색·미세 대비 단계로 관리한다.
7. **승인된 단계만 재사용한다.** 미통과 기하를 마스터로 승격하지 않는다.

## 7. 이번 사례에서 확인된 사실

- 프롬프트만으로 “같은 소실점”을 지시해도 생성형 모델은 꼭짓점을 이동시켰다.
- 카메라별 이미지를 각각 생성하면 렌즈 차이와 장면 차이가 섞였다.
- 공통 마스터에서 Sony·Canon을 분기하자 비교 공정성이 개선됐다.
- 분석적 35mm 프록시는 두 소실점의 y차이를 `0px`로 만들 수 있었다.
- 프록시를 사진화하는 과정에서는 다시 기하 드리프트가 발생할 수 있으므로 최종 사진도 재측정해야 한다.

## 8. 최종 산출물 등급

| 등급 | 조건 | 사용 가능 범위 |
|---|---|---|
| Concept | 구성만 승인 | 아이디어 검토 |
| Visual | 육안상 자연스러움 | 무드보드·프레젠테이션 |
| Controlled | 공통 마스터와 단계 기록 보유 | 카메라·색 A/B 비교 |
| Geometry-verified | 투시·수직·접지 수치 통과 | 건축·가구 표현 |
| Production | Geometry-verified + 인물·광학·색·출력 QC | 최종 납품 |

현재 `IMG_20260922_0001`의 생성형 후보는 `Controlled` 이하이며, 분석적 35mm 프록시만 기하 계산에서 통과했다. 사진화 결과는 별도 검증 전까지 `Geometry-verified`로 부르지 않는다.
