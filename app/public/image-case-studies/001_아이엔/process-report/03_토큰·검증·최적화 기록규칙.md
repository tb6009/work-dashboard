# 토큰·검증·최적화 기록규칙

## 1. 목적

이미지의 품질뿐 아니라 어떤 제작 경로가 더 적은 호출·시간·재작업으로 목표를 달성했는지 비교하기 위한 기록 규칙이다.

## 2. 작업별 필수 기록

| 필드 | 설명 |
|---|---|
| `project_id` | 이미지 또는 장면 ID |
| `process_version` | 01 prompt-first / 02 geometry-first |
| `stage` | 현재 제작 단계 |
| `input_assets` | 사용한 원본·제어도·프록시 |
| `prompt_revision` | 프롬프트 버전 |
| `generation_calls` | 이미지 생성 호출 횟수 |
| `analysis_calls` | 분석·검증 횟수 |
| `elapsed_time` | 가능할 때 실제 경과시간 |
| `token_usage` | 도구가 제공할 때만 실제값 기록 |
| `validation` | 투시·형태·접지·조명·색 판정 |
| `failure_reason` | 실패 원인과 발생 단계 |
| `reusable_assets` | 다음 버전에 재사용 가능한 자산 |

## 3. 토큰 기록 원칙

- 실제 사용량을 도구에서 받지 못하면 숫자를 추정해 확정값처럼 쓰지 않는다.
- 상대값은 `1×`, `2–4×`처럼 계획 범위로 표시한다.
- 텍스트 토큰과 이미지 생성 호출을 분리한다.
- 긴 프롬프트가 항상 더 정확한 것은 아니므로 프롬프트 길이보다 실패 재호출 수를 함께 본다.

## 4. 검증 횟수 기록

```json
{
  "stage": "02_perspective",
  "attempt": 1,
  "machine_validation": "passed",
  "human_validation": "pending",
  "metrics": {
    "vp_y_difference_px": 0.0,
    "vertical_deviation_deg": 0.0
  },
  "next_action": "hold_for_human_review"
}
```

검증 실패 후 같은 단계에서 재작업하면 `attempt`를 올린다. 다음 단계로 넘어갔다가 되돌아오면 원인 단계와 발견 단계를 모두 기록한다.

## 5. 최적화 지표

| 지표 | 계산 | 의미 |
|---|---|---|
| First-pass pass rate | 최초 통과 단계 / 전체 단계 | 초기 명세 품질 |
| Rework rate | 재작업 단계 / 전체 단계 | 공정 안정성 |
| Calls per approved image | 총 생성 호출 / 승인 이미지 | 생성 효율 |
| Validation yield | 통과 결과 / 검증 결과 | 후보 품질 |
| Reuse ratio | 재사용 자산 / 전체 자산 | 하네스 효율 |
| Variant marginal cost | 파생 제작비 / 파생 수량 | 다중 앵글 효율 |

## 6. 비교 시 금지사항

- MAE 하나를 원본 정체성 보존도 전체로 부르지 않는다.
- 선명도 하나를 이미지 품질 점수로 부르지 않는다.
- 육안상 좋아 보인다는 이유로 투시 수치 실패를 통과시키지 않는다.
- 소실점 검출 방법이 다른 버전의 오차를 단순 개선율로 나누지 않는다.
- 실제 RAW·렌즈 프로파일 없이 카메라 물리 복제를 주장하지 않는다.

