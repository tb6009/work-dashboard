01 버전 — 프롬프트에서 정확한 이미지 제작

1. 정의

텍스트 프롬프트, 원본 이미지, 투시 가이드 이미지를 생성형 모델에 입력하고 완성 이미지 또는 수정 이미지를 직접 얻는 방식이다. 이번 프로젝트의 원본→v1→v2→v3→v4 과정이 여기에 해당한다.

2. 기본 프로세스

요구사항 작성
→ 원본 분석
→ 오류를 프롬프트로 명시
→ 전체 또는 국소 재생성
→ 육안 비교
→ 문제 부위 재프롬프트
→ 카메라·렌즈·색 표현 추가
→ 최종 선택

3. 프롬프트 구조

Use case
Input image role
Primary request
Scene/backdrop
Subject and pose
Composition/framing
Perspective constraints
Lighting/mood
Camera/lens interpretation
Color finish
Locked invariants
Avoid list

정확도를 높이려면 “투시를 맞춰라”가 아니라 다음처럼 대상과 불변 조건을 분리해야 한다.

  • 테이블은 하나의 직육면체로 유지
  • 테이블과 미디어 콘솔은 동일한 두 소실점을 사용
  • 수직 구조물은 같은 카메라의 수직축을 사용
  • 인물·책·소파 접촉은 유지
  • 수정 대상 이외의 얼굴·강아지·창·외부 풍경은 변경 금지

4. 검증 루프

검증 질문 실패 시 수정 범위
구성 주 피사체와 시선 흐름이 맞는가 전체 프레이밍
투시 같은 축 선들이 같은 소실점으로 모이는가 가구·공간 구조
형태 손·다리·책·의자가 완전한 구조인가 대상 전체 형태
접지 가구 다리·발·소품이 표면에 닿는가 접촉과 그림자
조명 광원 방향과 그림자가 일치하는가 조명만 수정
렌즈 왜곡과 심도가 화면 전체에서 연속적인가 광학 효과만 수정
색 피부·중립색·하이라이트가 안정적인가 색보정만 수정

5. 토큰·호출 최적화

  1. 최초 프롬프트에 모든 문제를 넣기보다 우선순위 1개만 수정한다.
  2. 매 반복마다 불변 조건을 짧게 다시 적는다.
  3. 동일한 실패가 두 번 반복되면 프롬프트를 늘리지 말고 제어 이미지 또는 02 방식으로 전환한다.
  4. Sony·Canon을 각각 처음부터 생성하지 말고 가능하면 공통 장면에서 분기한다.
  5. 비교 대상이 아닌 소품 변화는 금지해 재검토 범위를 줄인다.

6. 장점

  • 초기 결과가 빠르다.
  • 인물·식물·천·빛 같은 유기적 요소가 자연스럽다.
  • 정확한 3D 모델이 없어도 제작할 수 있다.
  • 아이디어와 분위기를 다양하게 탐색하기 쉽다.

7. 한계

  • 프롬프트의 “정확한 소실점”은 픽셀 구속조건이 아니다.
  • 수정할 때마다 얼굴·가구·외부 풍경이 함께 변할 수 있다.
  • 카메라 브랜드 표현과 장면 재구성 차이가 혼합된다.
  • 반복 프롬프트가 길어져도 동일 오류가 해결된다는 보장이 없다.
  • 다른 카메라 앵글을 만들 때 공간 구조를 다시 추정한다.

8. 중단·전환 기준

다음 중 하나가 발생하면 01 방식의 반복을 중단하고 02 방식으로 전환한다.

  • 동일 투시 오류가 2회 이상 반복
  • 건축·가구 직선이 납품 기준의 핵심
  • 동일 공간에서 3개 이상의 카메라 앵글 필요
  • 카메라·렌즈 비교에서 장면을 완전히 동일하게 유지해야 함
  • 재생성으로 인물 정체성이나 제품 형태가 계속 변함

9. 이번 사례의 판정

  • v2는 원본 픽셀 변화가 가장 작아 자연교정에 유리했다.
  • v3·v4는 인물 포즈와 카메라 감성을 개선했지만 투시 기술검증을 통과하지 못했다.
  • 따라서 01 방식은 사진적 자연스러움에는 유효했으나 엄밀한 건축·가구 투시를 보장하지 못했다.
