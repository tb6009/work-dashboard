01 · Process

열 개의 게이트

한 장짜리 이미지 실험에서 시작해, 하나의 주제를 여러 페이지의 이야기로 설계하고 이중 평가를 통과한 것만 고해상도로 내보내는 파이프라인으로 바뀌었다. 각 게이트에는 통과 조건이 붙어 있고, 조건을 못 채우면 다음으로 가지 않는다.

G0브리프 잠금주 대상과 보조 대상, 게시 시점, 독자의 다음 행동을 먼저 정한다. 공식 근거가 없는 날짜·수치는 사용 금지 상태로 둔다.통과 조건 — 목적 1 + 대상 1·2차 + CTA 1 + 공식 근거 목록
G1공식 자료 수집대학 공식 홈페이지 → 입학안내 → 학과 페이지·공식 채널 순으로 훑고, 사실·이미지·작품명·연도·권리 상태를 자산대장으로 만든다.통과 조건 — 모든 사실 문장에 출처 · 모든 이미지에 권리 상태
G2콘텐츠 설계Hook을 A(작품)·B(공감)·C(과정·진로) 세 갈래로 만들어 보존한다. 5~8페이지의 Hook → 공감 → 증거 → 과정 → 의미 → CTA를 설계한다.통과 조건 — 페이지당 핵심 메시지 1개 · 본문 60~110자 · 정보 단위 9개 미만
G3페이지 수·레이아웃 결정정보 구성 → 그루핑 → 위계 → 정보 체계 → 레이아웃 → 비주얼 순서로 간다. 이미지가 증거면 이미지 1차, 일정·수치가 핵심이면 텍스트 1차.통과 조건 — 페이지마다 1차 진입점과 이미지 역할을 한 문장으로 설명 가능
G4PLAY 5.5 적용계열 Main Color를 주색으로, Tint & Shade를 보조로. 로고 회전·왜곡·임의색·효과·복잡한 배경 위 배치는 금지.통과 조건 — 브랜드 하드게이트 위반 0건
G5초기 시안1080×1350 기준이되 2× 렌더 가능한 HTML 구조로 만든다. 파일럿 한 개를 먼저 완성해 평가한다. audit.mjs가 크기·오버플로·서체 로딩을 자동 검사한다.통과 조건 — 모바일에서 확대 없이 읽힘 · 자동 검사 오버플로 0건
G6독립 평가평가 에이전트를 제작 에이전트와 분리한다. 사용자 관점 50점(적절성·Hook·가독성·이미지·흐름·행동 유용성·정서) + 제작자 관점 50점(공식성·정합성·브랜드·레이아웃·정보량·권리·확장성·CTA).통과 조건 — 총점 80 이상 · 사용자 40/50 이상 · 제작자 40/50 이상
G7수정 또는 대안 전환부분 문제면 해당 페이지를 유지/수정/교체/삭제/분리한다. 방향 문제면 A를 반복하지 않고 B·C 스토리보드로 갈아탄다. 공식 자산이 없으면 이미지 생성으로 위장하지 않고 자산 요청 질문으로 전환한다.
G8고해상도 제작원본 2160×2700 / 게시본 1080×1350 sRGB PNG. 텍스트는 생성 이미지가 아니라 레이아웃 엔진에서 조판한다.통과 조건 — 페이지별 PNG + 전체 보드
G9최종 QA·게시 패키지작품명·학생명·학과명·교과명·연도를 원문과 대조하고 200% 확대에서 로고·텍스트·이미지 결함을 본다.통과 조건 — 하드게이트 4종 전부 PASS일 때만 READY_TO_PUBLISH
02 · Evidence

무엇이 실제이고 무엇이 합성인가

시안은 실제 학생 100명을 조사한 결과가 아니다. 공식 사실, 행정데이터에서 관찰한 행동, 그 관찰로 만든 규칙 기반 합성 패널 — 세 층을 섞지 않고 각각 무엇을 할 수 있는지 따로 적었다. 이 구분을 문서에 박아두지 않으면 합성 결과가 나중에 “조사 결과”로 둔갑한다.

층위성격시안에서 맡은 역할
공식 모집요강공식 사실학과명 · 2년제 · 입학정원 · 전형과 인원 · 전공발견학기제 · 4단계 지원 · 문의처. 화면의 모든 숫자와 제도 설명은 이 범위를 넘지 않는다.
입시행동 데이터실제 관찰값“전공을 못 정했다”는 심리는 행정데이터로 직접 잴 수 없다. 대신 같은 입시연도에 서로 다른 학과에 지원한 행동을 전공 탐색 수요의 대리변수로 썼다. 개인 식별값은 집계에만 쓰고 문서에 남기지 않았다.
합성 페르소나합성관찰된 비율을 정수로 할당해 만든 반응 모형. 표지 문안 후보를 비교하는 데만 썼다. 실제 응답이 아니다.
합성 평가 연산규칙 기반 계산복합점수와 평가요소값은 계산량이지 응답 수가 아니다. 문서에 “독립 응답 N건”으로 쓰지 않았다.
생성 비주얼AI 생성보존된 PNG 30개 중 AI 생성·편집 결과 25개, 단순 규격화 5개. 프로젝트 전용 학습·파인튜닝은 0회. 폐기된 시안은 셀 수 없으므로 25는 확인 가능한 최소치다.

지원자 단위 수치와 세그먼트 표는 🔴 내부 기획 전용으로 분류되어 이 공개 기록에 싣지 않는다.

03 · Undo

되돌린 것들

1차 40페이지를 모바일에서 다시 보고 되돌렸다. 되돌림은 취향 문제가 아니라 대부분 “작게 보면 안 읽힌다”와 “근거가 모자란다” 둘 중 하나였다.

되돌린 것왜반영
이미지 위 각진 흰색 박스글을 얹으려고 사진 위에 흰 판을 깔면 이미지가 배경으로 죽는다. 이미지의 네거티브 스페이스를 찾아 그 자리에 글을 앉혔다.SET A v2
전 페이지 고밀도 키 이미지표지의 강한 이미지를 모든 페이지에 쓰니 글이 묻혔다. 표지만 키 이미지를 유지하고 세부 페이지용 저밀도 파생 이미지를 따로 만들었다.SET A v2
기계적인 카드 나열네 개의 지원을 세로 카드 4장으로 늘어놓으니 정보가 아니라 표처럼 보였다. 2×2 면으로 묶고 면마다 한 줄 설명만 남겼다.SET A v2
화면 위 근거 표기출처를 화면에 노출하니 SNS 카드로서 읽히지 않았다. 화면에서는 지우고 evidence/와 README에는 그대로 보존했다.SET A v2
SET B(경험 우선형)다섯 세트 중 하나를 이후 프로세스에서 제외했다. A·C·D·E 32페이지만 v2로 이어진다.v2 계보
“새 이미지를 더 만든다”C·D·E v2에서 배경이 약한 페이지를 보완할 때 새로 생성하지 않고 기존 맥락 이미지를 다시 드러냈다. 기준 세트와의 시각적 일관성이 새 그림보다 중요했다.C·D·E v2

04 · Gate

80점은 게시 허가가 아니다

평가 에이전트는 제작 에이전트와 분리한다. 사용자 관점 50점과 제작자 관점 50점을 따로 매기고, 총점 80·각 관점 40을 모두 넘겨야 고해상도로 간다. 그런데 파일럿에서 점수는 넘었는데 내보낼 수 없는 상태가 나왔다.

파일럿총점판정
2027 수시 2차 안내84 / 100사용자 44 · 제작자 40. 수치·하위 점수·자동 감사 모두 통과 → 고해상도 내부 검토본 제작 승인. 외부 게시는 불가.
포트폴리오 vs 면접80 / 100사용자 43 · 제작자 37로 제작자 관점 통과선 미달. 작품명·제작진·연도·재사용 권리가 비어 있었다.

그래서 규칙을 하나 더 넣었다 — 수치 점수와 외부 게시 가능 여부를 분리한다. 하드게이트(사실 오류·로고 오용·미확인 권리·최소 글자)가 하나라도 FAIL이면 점수와 무관하게 READY_TO_PUBLISH로 올리지 않는다. 시안에 박힌 INTERNAL TEST · NOT FOR PUBLISHING 워터마크도 미관 감점이 아니라 상태 표지로 취급한다.

07 · Principles

정리 — 여덟 개

1공식 근거가 없는 숫자는 쓰지 않는다. 비워두고 질문으로 넘긴다
2만든 사람이 채점하지 않는다. 평가 에이전트를 분리한다
3점수와 게시 허가는 다른 판정이다. 하드게이트 하나면 점수는 무효다
4실제와 합성을 문서에서 갈라둔다. 계산량을 응답 수로 쓰지 않는다
5“공식 사이트에 있음”과 “재사용 허가”는 다른 말이다
6모바일에서 안 읽히면 글자를 줄이지 말고 문장을 줄이거나 페이지를 나눈다
7보완은 새로 만드는 것보다 이미 있는 것을 다시 드러내는 쪽을 먼저 본다
8시안 상태 표지를 지우지 않는다. 워터마크는 감점 요소가 아니라 상태다
내부 제작 시안 · 외부 게시 승인 전 — 이 페이지의 캐러셀은 학과·입학지원팀 감수를 받지 않은 제작 시안이다. 등장하는 인물·수업·작품 장면은 생성형 콘셉트 이미지이며 실제 계원예술대학교 학생·수업·작품이 아니다. 사실 문장은 2027학년도 공식 모집요강에서 직접 확인한 범위(5·18·42·57·80쪽)를 넘지 않는다.
